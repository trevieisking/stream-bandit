# Code Labs Page and Specialist Tool Single-Owner Contract

**Status:** authoritative page-architecture gate for the Code Labs recovery branch.

This contract prevents shared pages, support tools and compatibility helpers from becoming competing workflow engines.

## Preservation rule

Preserve every working capability. Correct or rearrange only the route, state authority or ownership boundary that conflicts.

A duplicated capability is not automatically removed. It is classified as one of:

- canonical owner;
- bounded support view;
- local draft or backup;
- read-only evidence view;
- compatibility adapter;
- retired static notice.

## Canonical owners

| Responsibility | Sole canonical owner |
| --- | --- |
| Visible sidebar and route order | V282 shared shell loader |
| Normal next-step workflow decision | Workflow Hub |
| Authoritative project/file/job/packet/test state | Atomic Supabase workspace engine |
| Page grouping and scroll reduction | Page Workspace runtime and tabs |
| Page inspection and bounded field assistance | Buddy Page Bridge |
| Repository branch/commit/PR execution | Protected Writer route |
| Deterministic final review | Code God |
| Repair-specific evidence plan | Dynamic Checklist Builder |

## Specialist tool roles

- **Start Guide:** optional plain-English draft intake. It may prepare values but must not overwrite newer backend truth.
- **Fix Wizard:** optional read-only guidance. It must use the same next-step policy as Workflow Hub.
- **AI Handoff:** read-only emergency/export package. It must not mutate workflow authority.
- **Checklist Builder:** builds checks from the exact repair, page, action, dependencies and evidence requirements. A fixed generic checklist is insufficient.
- **Context Packet / Canvas Receipt:** exact context and receipt evidence bound to source and candidate hashes.
- **Route Scanner:** source inspection support. Scanner output is evidence, not automatic authority.
- **Read-only Proof:** current backend proof surface.
- **Owner Read Proof:** retained static retirement notice only.
- **Buddy Tools:** assistant-access utilities, memory recovery and bounded local helpers. They must remain discoverable without becoming a second workflow engine.

## Buddy Page Bridge modes

Each page family must declare one mode:

- `draft_fields` - local non-sensitive intake only;
- `read_only_context` - inspect and package context only;
- `assisted_page_fields` - explicit mapped fields, local receipt and one-step undo;
- `protected_action_only` - any authoritative change must enter the atomic backend;
- `blocked` - secrets, production actions and GitHub execution.

The bridge must never directly own backend workflow state, Writer execution, deployment or protected repository operations.

## Duplicate-owner rules

1. V282 owns the visible sidebar. Older helpers may retain route metadata for compatibility but must not redraw the menu after V282 takes ownership.
2. Workflow Hub owns the normal next-step decision. Support pages may explain or display that decision but must not maintain an independent policy.
3. Page Workspace owns grouping only. It must not mutate workflow state.
4. Buddy Page Bridge owns page inspection and bounded local assistance only.
5. `codeLabsV1State` is draft/cache compatibility state, not authoritative backend truth.
6. Checklist Builder must derive checks from the exact operation and evidence contract.
7. Support, proof and specialist pages remain discoverable from the Specialist Tools drawer or Help.
8. Retired proof pages remain static notices and must not restart obsolete OAuth or backend routes.

## Required repair-specific checklist fields

The dynamic checklist must be capable of recording:

- operation ID and expected workspace state;
- repository, branch and target file;
- source hash and candidate hash;
- page and page role;
- requested action;
- preserved capabilities;
- affected helpers and dependencies;
- authentication, owner scope and entitlement checks;
- database, browser and GitHub boundaries;
- rollback, replay and fencing tests;
- CG Repair Lab and Code God findings;
- required, performed, passed, failed and not-run states;
- evidence source for every material check;
- user-added repair-specific checks.

A checklist cannot mark itself PASS. It only records evidence for the promotion controller.

## Completion definition

This page-architecture battle passes only when:

1. one visible route owner is proven;
2. one normal next-step owner is proven;
3. support pages use declared bounded roles;
4. Buddy Bridge modes are explicit;
5. the checklist is repair-specific;
6. support and proof pages remain discoverable;
7. no working capability is lost;
8. browser regression tests show no menu flicker, duplicate panels or competing state writes.

This contract does not authorise a deployment, migration, merge or production change.
