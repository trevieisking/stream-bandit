What is already locked

Core game

  • 8 Set One elements: Astral, Ember, Gale, Grove, Shade, Stone, Tide, Volt.
  • 193 Set One gameplay identities.
  • Eight exact 60-card starters.
  • Baby → Teen → Adult evolution; Standalone valid; Mythic separate.
  • Printed HP 40–390.
  • Vanguard + four Reserve + six Reward Cards.
  • Essence, Tactics, Shield and conditions.
  • First player cannot attack on first personal turn.
  • Starbound separate from Mythic.

Product/economy

  • Exactly three currencies: Battle Pass Tokens, Trade Tokens, Shop Coins.
  • Normal cards keep up to four copies; Mythic keeps one.
  • Arcade is the first normal non-ranked mode.
  • Private rooms remain valid for friend/test battles and cannot farm normal Arcade rewards.
  • 100-tier Battle Pass with a reward every tier.
  • Three daily achievements.
  • Standalone TCG product shell; shared Stream Bandit account identity.

Completed foundations

  • Hidden canonical state + seat-private views.
  • Nonce/revision idempotent command path.
  • Core play/evolve/Essence/Relic/Realm/turn paths.
  • Damage, Shield, recoil, effect damage and major conditions.
  • Starbound consumption foundation.

  • Generic v0.2 runtime registry marker/snapshot boundary.
  • Structured withdrawal.

Still required before real private-alpha confidence

  • Finish Runtime Pass C: remove remaining printed-English attack authority and make structured attacks authoritative wherever parity is proven.
  • Runtime Pass D: route attack/Ability selections through the generic private pending-choice owner.
  • Runtime Pass E: generic Ability / Essence / Relic / Realm listeners and source-instance lifecycle state.
  • Runtime Pass F: remove remaining ordinary Set One prototype aliases/card-ID shortcuts only after parity proof.
  • Battle Lab deterministic scenario injection + source/target instance event trace.
  • Hidden hand/deck/Reward choice completion.
  • Reconnect/resume and adversarial stale/replay/simultaneous-command tests.

Remaining build order

1

Finish structured battle-runtime parity

Complete Runtime Passes C–F without breaking the current protected v0.1 production baseline. Remove legacy English/card-ID authority only where the structured replacement is proven.

2

Repair the economy/copy migration rule

Remove obsolete global one-Mythic-total / Legendary restrictions and preserve the current rule: ordinary identity max 4, Mythic identity max 1, Essence separate allowance.

3

Complete generic choices, reconnect and deterministic Battle Lab

Finish private selections, reproducible scenarios, event tracing and recovery paths before relying on visual UI testing.

4

Build Test Deck Battle / AI Test Match

Use the same legal server action path, seeded randomness and no hidden-information cheating. No rewards/rank/XP for QA matches.

5

Build the actual standalone player UI

Public landing/sign-in, authenticated game home, premium card renderer, one-screen drag/drop battlefield, Collection, Deck Builder, Shop, Pass, Profile and Sets.

6

Promote private-alpha backend only after exact-head gates

Apply the reviewed additive migrations and Edge Functions only when TCG Validation, migration replay and functional smoke all pass the exact candidate head.

7

Two-account real battle

Desktop + phone: sign in, choose starter/deck, enter matchmaking/private battle, complete setup, play to victory and persist the result without manual database intervention.

8

Balance and production release

AI simulation matrix, human balance tuning, reconnect/private-state tests, economy receipt/retry tests, final accessibility/mobile checks, then production promotion.

Can the game be fully ready today?

What can be ready immediately

The master-plan/control surface can be live independently, and safe branch-only TCG ticks can continue one at a time with exact evidence.

What should not be promised today

A fully production-ready TCG. The remaining work includes several substantial runtime passes, the final player-facing application, deployment gates and a genuine two-account complete battle. Those are engineering/release gates, not cosmetic polish.

Practical target: first reach a boring, deterministic, complete two-player private-alpha battle. Collection, shop, ranked, Battle Pass polish and public SEO can then be layered without risking the battle engine.

Promotion rules

PROMOTE branch ticks

When the exact bounded change, regression coverage and exact-head workflows are green.

HOLD production

Until runtime parity, exact-head database/function evidence and the full desktop/phone battle test pass together.

Safety boundary

No TCG task may require unrelated Stream Bandit, DJ, Web Builder or social-media changes. No direct main runtime write. No production database/function deployment just because the integration branch is mergeable.
